# FocusRestore

用于 HyperOS 3/4 的实验性 LSPosed 模块，尝试恢复 HyperOS 2 的 Focus（焦点通知）状态栏显示路径。

仓库地址：`https://github.com/ImKani/FocusRestore`

- 图标与文字间距可独立调整为0～24dp，默认跟随系统；图标尺寸恢复跟随系统，不再提供独立“默认8dp”入口，已有自定义值保留。
- OS4 分隔线负间距保留靠近/重叠效果，同时让滚动正文遵守自己的显示区域，避免滑入固定图标。
- 配置中个别字段类型异常时只恢复该字段的默认值，其他合法配置继续加载。
- 原生横幅接口不兼容时明确记录部分清理，减少同类取消接口缺失的重复异常；普通通知背景修改使用独立状态。

当前默认值：

- 横屏显示与触控宽度默认600dp，超级岛转换和点击横幅默认开启；自定义触控范围仍默认关闭。
- 焦点图标大小、图标与文字间距及分隔线尺寸默认跟随系统；外观数值显示当前资源尺寸，已有自定义值保留。
- 高级页功能组支持收起展开，精简重复说明，保留smallIcon提示与实验性标记。
- 无用户配置的首次启动自动选择HyperOS 3/4，继续提供手动切换。

上述默认值用于缺少对应设置或恢复默认时；已保存的开关、宽度和图标自动模式保留。触控宽度仅默认值与显示宽度一致，之后仍独立调整。

长按优先交给系统通知行处理；媒体通知缺少通知行时沿用横幅的媒体会话打开入口。通知已移除或焦点已切换时不执行打开。


## 功能概述

- 在 HyperOS 3/4 上显示和管理焦点通知。
- 可将符合条件的超级岛内容转换为焦点通知，并支持应用白名单。
- 支持设备通知、媒体焦点通知、焦点内容宽度限制、滚动显示和分隔线显示。
- 支持按系统界面版本选择 HyperOS 3 或 HyperOS 4；切换后需重启 SystemUI 或设备生效。
- 支持实验性的焦点通知点击行为、媒体横幅和无缝流转入口。
- 支持焦点图标来源优先级、超级岛解析图标优先，以及设备通知独立反色。
- 模块作用域为 `com.android.systemui`，不要求 KernelSU 模块。

## 设置项说明

设置模块从 LSPosed 模块详情进入，不显示桌面图标。页面分为“主页”“高级”“关于”：主页设置系统版本、超级岛转换和焦点显示；高级设置图标、点击/长按/滑动、独立触控范围、滚动和连接符；关于页提供配置导入导出。设置修改会自动保存，宽度与时长等滑动条在松手后提交，切换页面会保留当前设置。涉及 SystemUI Hook 的选项需要手动重启 SystemUI 或设备后完整生效。

### 主页：系统界面版本

- **HyperOS 3 / HyperOS 4**：仅首次两份存储都无用户配置时读取 `ro.mi.os.version.name` / `ro.mi.os.version.code`，识别3或4并保存到现有模式设置；无法识别时保留OS3默认并记录原因。手动选择按钮与切换逻辑不变，已有配置、配置导入及系统升级不会触发重新探测；切换后仍需重启系统界面。

### 主页：超级岛转换

- **转换超级岛内容为焦点通知**：默认开启。开启后尝试将符合条件的超级岛内容转换为焦点通知。
- **焦点内容模式**：支持“展开全文本解析”和“药丸左右拼接”，需开启超级岛内容转换。
- **超级岛白名单**：选择需要强制转换的应用，需开启超级岛内容转换。原生焦点默认优先；白名单只对确有可转换内容的通知生效。

### 主页：焦点显示

- **限制焦点通知宽度**：默认开启；关闭后内容宽度跟随系统。此开关控制内容显示，触控扩展由高级页的独立开关决定。
- **最大宽度**、**横屏最大宽度**：分别调整竖屏显示上限 `80～400dp`、横屏显示上限 `80～1600dp`，默认分别为 `160dp` / `600dp`；两条滑动条仅在宽度限制开启时可调整，关闭后置灰并保留已保存值。
- **启用媒体焦点通知（实验性）**：默认关闭。
- **隐藏其他通知图标（HyperOS 4）**：默认开启，仅影响焦点显示期间的其他通知图标。
- **显示焦点分隔线**：默认开启，HyperOS 3/4 均支持；样式、粗细与两侧间距在高级页调整。
- **最大显示时间（秒）**：`0` 表示不限制，支持 `2～3600` 秒；超过时间只隐藏状态栏焦点，不取消通知。
- **超时豁免名单**：名单内的应用不受最大显示时间限制，按系统自己的时长显示；与超级岛白名单相互独立。

### 高级：焦点图标

高级页各功能组默认收起，点击标题或右侧矢量箭头展开或收起（收起时向下，展开时向上），允许同时展开多组；切页和 Activity 重建保留本次展开状态，退出后不作为配置备份。主页的“焦点显示”也可折叠。界面只保留必要提示，本节提供完整说明。

- **焦点图标优先级（按住拖动排序）**：长按一行后上下拖动，越过相邻行中线即调整顺序，松手自动保存；普通上下滑动仍用于滚动页面。取消、多指触摸、暂停或切页放弃本次拖动。图标资源加载或绘制失败时继续尝试下一来源，支持以下六种完整排列，新安装默认第1种。设备通知不参与此顺序。

排序列表上下各保留6dp留白；手指进入第一项上半行或最后一项下半行即可调整到首尾，无需继续拖入宽空余区。右侧三个短横统一对齐，整行都可长按拖动。

| 排列 | 顺序 |
|---|---|
| 1（旧值0） | 主题应用图标 → 焦点专用图标 → 通知小图标 |
| 2（旧值1） | 焦点专用图标 → 主题应用图标 → 通知小图标 |
| 3（旧值2） | 通知小图标 → 主题应用图标 → 焦点专用图标 |
| 4（新增） | 主题应用图标 → 通知小图标 → 焦点专用图标 |
| 5（新增） | 焦点专用图标 → 通知小图标 → 主题应用图标 |
| 6（新增） | 通知小图标 → 焦点专用图标 → 主题应用图标 |

通知小图标（`smallIcon`）依赖应用自行适配。国内不少应用未提供适合状态栏的单色透明图标，反色后可能显示为大白块；遇到这种情况，建议选择“应用图标优先”或“焦点专用图标优先”。

- **优先使用超级岛解析图标**：独立开关，默认关闭。开启后优先取有效岛区域/已知图标节点中的图标，没有可用图标则回到自定义顺序；通知 ticker 专用图仍属于“焦点专用图标”，横幅背景与任意根图片不作为岛图标。
- **超级岛解析图标与通知小图标跟随状态栏反色**：默认开启，保留透明度和透明孔洞；应用图标保留原色，焦点专用图标使用通知提供的浅深版本，缺少深色版本时沿用浅色来源。

应用图标优先使用 SystemUI 的主题图标管线，失败后尝试应用原图。主题动态图标显示系统管线提供的静态图像，不持续播放桌面动画。OS3 原生 Focus 的独立图标也适用；原生 RemoteViews 内部图标仍由 ROM 管理。

- **焦点图标大小**：默认跟随当前ROM，支持自定义1～32dp、1dp步进；参考OS3/OS4资源均为16dp，资源不可用时按16dp回退。已有自定义8dp等数值保留。OS3原生与转换Focus、OS4模块独立图标及设备图标都使用该尺寸，图标控件与绘制尺寸同步。图源自身透明留白和超级岛图标安全边距仍保留；通知自带RemoteViews内部图标仍由通知布局管理。大图标最终受状态栏父布局高度约束。
- **图标与文字间距**：默认跟随SystemUI的 `focused_notif_content_start` 资源，参考OS3/OS4均为3dp；支持自定义0～24dp。只调整独立状态栏图标到正文容器的间距，不改变通知自带RemoteViews内部布局。旧配置/旧备份缺少此项时使用跟随系统。
旧配置缺少新优先级时：旧 smallIcon 开启迁移为“通知小图标优先”；否则旧超级岛图标开启迁移为“焦点专用图标优先”；其余迁移为“应用图标优先”。超级岛开关保留原值，迁移并保存后分别控制；配置备份遵循相同迁移规则。

### 高级：焦点分隔线

- **焦点分隔样式**：竖线（默认）、圆点、斜线、短横线，固定在正文之外，颜色跟随状态栏。
- **分隔线前／后间距**：分别控制时间到分隔线、分隔线到焦点图标的间距，支持−24～24dp，默认跟随系统；负值允许分隔线和相邻区域靠近或重叠，但不会改变独立的图标与文字间距。时间侧变化会移动后续整组焦点，图标和文字之间的相对距离保持。RTL布局下按起始／结束方向排列。
- **分隔线粗细**：默认读取系统 `line_width` 资源，参考OS3/OS4均约1.38dp；也可设为1～4dp，圆点的直径最小3dp。

跟随系统时显示当前实际的“X dp”数值，点击滑条下方的“跟随系统”恢复自动；有独立默认值的项目同时显示“默认”，点击后恢复默认并以强调色标记当前状态。拖动滑块会切换为自定义值，宽度滑条两端显示合法范围。负间距仍支持−24～24dp，自动状态不占滑条刻度。

设置页与OS4重建布局读取已安装SystemUI的 `status_bar_notification_padding_end`（前间距）、`focused_notif_view_padding_start`（后间距）、`line_width`（粗细）和 `focused_notif_content_start`（图标文字间距），参考值为4dp／6dp／约1.38dp／3dp。资源不可读时按这些已核实参考值降级并记录原因。OS3自动分隔线仍保留原生布局恢复；OS4参考APK已无旧Focus布局，这些是ROM存留资源，模块依资源独立重建，不代表复刻原生运行效果。分隔间距自动标记为−25，旧编码−1迁移；图文间距自动标记为−1，实际自定义范围从0开始，均不会把自动标记当成dp传入布局。

数值设置的显示值使用紧凑单行文本，不带背景；下方提供“默认”或“跟随系统”文字，点击后恢复对应状态并自动保存，当前状态使用强调色。适用于横竖屏显示宽度、横竖屏触控宽度、长按时间、滚动延迟、最大显示时间、图标大小、分隔线前后间距及粗细。宽度滑条两端显示合法范围，底部显示默认操作。显示和触控宽度默认竖屏160dp／横屏600dp，图标大小和图标与文字间距默认跟随系统，长按默认0.5秒，延迟默认0.2秒，最大显示时间默认0（不限制），分隔线数值默认“跟随系统”。最大显示时间的输入框仍可正常编辑；子项不可用时恢复文字同步置灰。

### 高级：设备通知图标

- **设备通知图标跟随状态栏反色**：独立开关，默认开启。仅作用于模块生成的设备通知，使用当前状态栏前景色；关闭保留设备图标原色。设备通知始终显示对应状态图标，不受上面的优先级及超级岛图标开关影响。

### 高级：点击行为

- **点击焦点通知展开横幅（实验性）**：默认开启。普通焦点通知使用通知横幅，媒体焦点使用媒体横幅；点击外侧可收起。
- **通知横幅背景**：属于短按横幅选项，可选“统一使用纯色背景”（默认）或“使用普通通知背景”。
- **点击媒体焦点通知**：属于短按横幅选项，可选“展开媒体横幅”（默认）或“直接展开流转界面”。
- **无缝流转入口**：属于短按横幅选项，可选“小米妙播”（默认）或“安卓原生”；小米妙播不可用时自动回退安卓原生。
- **长按焦点通知模拟通知列表点击（实验性）**：默认关闭；在 HyperOS 3/4 上长按焦点通知时，复用横幅无控件区域的打开链路：优先通知行点击，媒体通知沿用媒体会话入口。
- **长按时间**：滑动条支持 `0.2～10` 秒，步进 `0.1` 秒，默认 `0.5` 秒，实时显示当前值；滑动、多指触摸、取消或焦点切换会取消等待。
- **左右滑动切换和收起焦点通知（实验性）**：独立开关，默认关闭。左滑切换下一项，右滑反向切换；队列包含一个空白位置，可收起全部焦点，通知仍保留在下拉通知栏。全部收起后在原焦点位置继续左右滑动可恢复；恢复区的宽度规则见下方“触控范围”。
- **旧版：打开通知内容（实验性）**：保留旧版打开通知内容行为。
- **直接打开失败时模拟通知列表点击（实验性）**：作为旧版打开通知内容失败时的兜底行为。

长按开关独立于短按横幅和旧版打开通知内容开关；长按成立后，松手不会再触发短按。媒体打开沿用横幅现有的媒体点击 intent 和应用入口兜底，不需要先展开横幅。

左右滑动参考 HyperOS 3/4 原生超级岛的隐藏队列与空白位置规则，适配为 Focus 的单位置显示；RTL 布局下左右方向反转。单指水平滑动超过 50dp 并松手才切换，短距离横滑不打开通知，下拉手势继续交给系统；取消、多指、长按已成立或通知换绑时不执行切换。普通内容更新保持当前手动选择，新焦点候选加入时重新按原有优先级选择；通知移除、媒体已被原生划掉或超过最大显示时间后不能通过滑动恢复。关闭开关会清除手动选择，恢复原有焦点选择行为。该功能复用焦点容器，超级岛大小岛双位置布局和动画未迁入；OS3/OS4 的实际手势、通知保留及恢复效果待各自真机验证。

“点击媒体焦点通知”和“无缝流转入口”需要同时启用媒体焦点通知；原有短按行为相关子项在“点击焦点通知展开横幅”关闭时不可用。

HyperOS 4 媒体焦点使用原生媒体卡片选出的当前媒体：首次加入或切换媒体需处于播放中，同一媒体暂停保留；卡片被划掉或当前媒体移除后隐藏，恢复播放并被原生重新选中后恢复。通知 Entry 留存或更新不会单独恢复焦点。妙播复用 ROM 的原生流转入口及窗口，CTA、退出和动画交给系统；成功分发后收起对应媒体横幅，原生入口不可用则回退安卓输出面板。媒体横幅本身仍使用现有渲染方式。相关私有接口已核对 OS3/OS4 参考 ROM；用户已确认 0.30.4 修复媒体横幅妙播重复隐私确认，其他设备及 OS3 行为仍需分别验证。

### 高级：触控范围

- **自定义焦点触控范围**：独立开关，默认关闭。关闭时恢复0.32.0的实际显示区域模式，不为短内容额外保留160dp空白触控区；旧配置升级和旧备份缺少此设置时也保持关闭。
- **竖屏触控宽度**：`80～400dp`，默认 `160dp`。
- **横屏触控宽度**：`80～1600dp`，默认 `600dp`，与竖屏分别保存；两条滑动条仅在自定义开关开启时可调整。

开启后，短按、长按和左右滑动共用扩展区域，短内容旁补出的空白也可操作；显示宽度和滚动仍使用主页的显示设置。自定义宽度作为最小操作宽度，焦点实际区域更宽时保留完整区域，最终受状态栏父布局的可用空间约束。此开关只控制操作范围，具体操作仍需要对应短按、长按或滑动功能开启；不扩大通知横幅内的播放、进度等独立控件。

收起后的滑动恢复区在自定义开启时采用当前方向的触控宽度；关闭时保留此前焦点的实际区域，状态栏重建后在时间旁使用0.32.0的96dp恢复区域。在收起期间关闭自定义时清除旧扩展范围，使用同一恢复兜底。关闭开关会保留已设置的横竖屏数值，供下次开启使用。

### 高级：滚动与兼容

- **启用往返滚动**：默认开启，使焦点内容在两端之间往返滚动。
- **兼容重试模式**：默认关闭，用于兼容部分 ROM 的滚动刷新问题。
- **滚动启动延迟**：支持 `0～5` 秒，步进 `0.1` 秒，默认 `0.2` 秒。

### 高级：内容连接符

- **普通内容**：设置普通焦点内容的连接符，默认 `·`，允许留空。
- **左右区域**：设置左右区域内容的连接符，默认 `·`，允许留空。

### 关于：配置导入与导出

关于页提供“导出配置”和“导入配置”，通过系统文件选择器保存或选择 UTF-8 JSON 文件，不申请存储权限。默认导出文件名为 `FocusRestore-yyyy-MM-dd-HH_mm_ss.json`（设备本地时间，例如 `FocusRestore-2026-10-11-12_41_58.json`）。备份包含当前43个用户设置，按功能分组，应用名单按包名排序；不包含应用缓存、内部保存状态或废弃设置。

导入先完整检查文件，再确认覆盖全部当前设置；文件中缺少的设置恢复兼容默认值，不与当前配置混合。旧显示横屏宽度缺失时继承所导入的显示竖屏宽度，旧连接符可作为两种连接符的回退；新增触控开关缺失时关闭，两种触控宽度缺失时分别使用160dp／600dp，不继承自定义显示宽度。取消或文件校验失败不写设置；保存失败会提示，双存储写入不保证跨存储事务。恢复后仍需手动重启系统界面完整生效。

配置文件带格式版本 `formatVersion` 和导出软件版本 `appVersion`（例如 `0.38.0(299)`），软件版本随实际导出构建自动填写，仅说明来源，不决定能否导入。手工编辑时 `appVersion` 必须保留为非空、最多64字符且不含控制符的文本；设置仍按字段类型、范围和结构校验。兼容基线为0.30.4的持久设置，不为0.31.0～0.31.3测试期间缺少软件版本字段的旧JSON增加迁移；旧版不保证能导入新增字段的新版备份。文件最多16 MiB，两份应用名单的包名文本合计最多64 Ki字符，避免页面状态保存超限；导入和导出使用相同限制。冲突的点击选项按设置界面现有优先级处理。文件包含应用名单等个人设置，请妥善保管。

## 日志抓取

Debug 和 Release 均保留模块加载版本、横幅点击与失败原因等运行日志；`DIAG` 详细诊断仅 Debug 输出。覆盖安装后需重启系统界面或整机才能加载新的 Hook。

安装或更新模块后，先在 LSPosed 中启用模块并确认作用域为 `com.android.systemui`。以下两种方案任选其一，二者都要求**先开始抓取，再手动重启系统界面**，这样可以同时记录 SystemUI 重启后的模块加载过程。不要在命令中自动执行 `killall` 或 `force-stop`，请使用设备上已有的“重启系统界面”方式手动重启。

### 手机端：MT 终端

在 MT 终端执行：

```sh
su
/system/bin/logcat -c
/system/bin/logcat -v threadtime HyperOS3FocusRestore:I FocusedNotifPromptView:I PromptViewAnimState:D AndroidRuntime:E '*:S' > /sdcard/focus-restore-0.38.0.log
```

保持命令运行，然后通过设备上的方式手动重启系统界面。完成复现后回到 MT 终端，按 `Ctrl+C` 停止抓取。日志保存在：

```text
/sdcard/focus-restore-0.38.0.log
```

### 电脑端：ADB + PowerShell

在电脑上执行：

```powershell
adb devices
adb logcat -c
adb logcat -v threadtime -b main -b system -b crash | Tee-Object -FilePath ".\focus-restore.log"
```

保持命令运行，然后在手机上手动重启系统界面。完成复现后回到 PowerShell，按 `Ctrl+C` 停止抓取。日志保存在执行命令时的电脑当前目录：

```text
.\focus-restore.log
```

### 新旧命令的区别

旧命令：

```sh
/system/bin/logcat -v threadtime HyperOS3FocusRestore:I FocusedNotifPromptView:I PromptViewAnimState:D AndroidRuntime:E '*:S' > /sdcard/focus-restore-0.29.1.log
```

新 README 同时保留了这类手机端过滤方案，并增加电脑端完整日志方案。两者区别如下：

- **手机端旧命令**：在设备本机运行，使用 Tag 白名单，只保存 `HyperOS3FocusRestore`、`FocusedNotifPromptView`、`PromptViewAnimState` 和 `AndroidRuntime`，文件位于 `/sdcard`，体积较小，适合直接发送分析。
- **电脑端新命令**：通过 ADB 读取 `main`、`system`、`crash` 三个缓冲区，不按 Tag 过滤，同时在 PowerShell 显示并保存到电脑的 `focus-restore.log`，信息更完整，但文件可能更大、包含更多隐私内容。
- **`-b main -b system -b crash`**：表示读取指定日志缓冲区；手机端过滤命令未指定缓冲区时使用系统默认缓冲区，通常主要是 `main`，因此可能遗漏 `system` 或 `crash` 中的旁证。
- **`Tee-Object`**：只负责把电脑端收到的日志同时显示和写入文件，不改变日志内容，也不是额外的过滤器。
- **手动重启SystemUI**：两种方案都不再由命令自动重启，避免不同 ROM 的重启命令差异；应在开始抓取后手动重启，以便记录模块重新加载过程。

如果需要在电脑端使用与手机端相同的 Tag 过滤方案：

```powershell
adb logcat -v threadtime -b main -b system -b crash | Select-String 'HyperOS3FocusRestore|FocusedNotifPromptView|PromptViewAnimState|AndroidRuntime'
```

日志中常见的 `DIAG` 行用于确认阶段性状态，例如模块加载、模式选择、设备通知投递、图标解析、焦点显示、取消和失败原因。日志只用于判断运行阶段，不等同于所有 ROM 上的显示成功；最终显示效果仍需结合设备画面确认。

### 日志判读建议

按以下顺序检查：

1. **模块是否加载**：搜索 `HyperOS3FocusRestore`、`loaded`、`hook` 或模式初始化信息。
2. **作用域是否正确**：确认日志来自 `com.android.systemui`，并且选择的 HyperOS 版本与设备一致。
3. **配置是否生效**：检查模式、超级岛转换、媒体焦点、图标和点击行为等设置是否为预期值。
4. **事件是否进入**：设备通知、媒体通知或超级岛通知应出现对应的接收、解析或候选记录。
5. **显示链路是否完成**：重点查看显示、投递、图标解析、横幅创建或取消阶段；出现 `failed`、`fallback`、`missing`、`timeout` 时，连同前后文一起保留。
6. **是否只是 ROM 显示差异**：如果日志显示投递和显示阶段完成，但画面仍异常，应同时记录 ROM 版本、横竖屏、浅色/深色状态、反色设置和复现步骤。

提交问题时建议提供：完整日志文件、模块版本、HyperOS 版本、设备型号、选择的系统界面版本、相关设置截图、复现步骤和实际画面截图。不要只截取单行日志，也不要上传包含个人通知内容、账号信息或设备标识的原始日志。

## 构建

源码使用 Android Gradle Plugin 8.7.3、Android SDK 35，Java 源级兼容 8。仓库未附带 Gradle Wrapper；请准备兼容的 JDK、Gradle 和 Android SDK，并配置 SDK 路径。

在仓库根目录使用已配置的 Gradle 执行：

```shell
gradle :app:clean :app:assembleDebug :app:assembleRelease
```

构建脚本引用 ImKani 本地保存的固定签名证书，证书私钥不随仓库提供。其他人自行构建时需配置自己的签名；不同签名的 APK 不能直接覆盖官方发布包。

构建产物位于 `app/build/outputs/apk/`，文件名为 `FocusRestore-<versionName>-<buildType>.apk`。ImKani 发布的各版本沿用同一固定的作者签名证书，Debug 和 Release 签名一致，便于覆盖升级并保留配置。

## 安装与验证

安装前确认设备已解锁、已启用 ADB，并已备份相关配置。安装不会自动启用 LSPosed 模块，也不会自动将作用域加入 SystemUI。

> **签名变更（0.34.2 起）**：本项目自 0.34.2 起改用作者签名证书，与此前各版本使用的固定测试证书签名不同，无法直接覆盖安装。从旧版本升级请先在模块“关于”页导出配置，再卸载旧版本、安装本版本，最后导入配置；卸载会清除模块内保存的设置，未导出的配置无法恢复。

```powershell
adb install -r '.\FocusRestore-0.38.0-debug.apk'
```

或安装 Release：

```powershell
adb install -r '.\FocusRestore-0.38.0-release.apk'
```

安装后：

1. 在 LSPosed 中启用 FocusRestore。
2. 仅勾选 `com.android.systemui` 作用域。
3. 打开模块设置，选择实际的 HyperOS 3 或 HyperOS 4 模式并保存。
4. 按设置提示重启 SystemUI 或设备，使 Hook 和配置完整生效。
5. 使用测试通知或实际通知复现，结合日志和画面验证。

卸载或回退前先关闭 LSPosed 模块并重启 SystemUI；出现 SystemUI 异常时优先禁用模块，不要反复安装不同签名的 APK。
